# Codex 目录超时与渠道列对齐修复

2026-11-02。本地实现、定向验收和独立复审完成。后续以 `7f592ffb` 提交并通过临时镜像快照部署到云悠、泉哥，见[快照部署记录](snapshot-catalog-align-20261102.md)。下文保留本地阶段证据。

## 原因和改动

Codex 0.165 的目录获取限时为 5 秒。本轮修复前，本机 App 内置 0.166.0-alpha.5.1 曾出现 `failed to refresh available models: request timed out`，网关对应请求为 499。Axon 原先最多等待来源 10 秒，四个并发槽可能先被只返回普通名单的来源占用。普通名单识别失败也不会缓存，因此每次刷新继续等待这些接口。

- `internal/server/biz/codex_catalog.go` 将远程来源预算调整为 3 秒，为传输、模型筛选和解析预留时间。内联 JSON、明确目录 URL、Codex 渠道及官方目录优先获取，普通兼容接口随后探测。模型指令来源仍按既有稳定优先级选取。
- `codex_catalog_models.go` 单独识别有效的 OpenAI `data` 名单。该结果按现有渠道、凭据、URL 和客户端版本隔离，并遵循 `no-store`、`no-cache`、`max-age`、`Age` 和最长五分钟规则。401、连接失败及损坏响应即时返回。新增错误分类只存在于进程内缓存。
- `channel-limiter-cell.tsx` 将标签、当前值、上限分区。`channels-table.tsx` 按已加载数据的本地化数字长度统一计算整表宽度，当前值右对齐，未配置上限保留空位。
- 更新中英文 Codex 集成指南、CHANGELOG 的 Unreleased 项及 fork 台账。无数据库迁移。

自动审批曾拒绝包含补齐本地测试数据与后台启动 Vite 的组合命令，原因仅为 `blocked by policy`。拆分明确范围的本地操作并改用工具托管 Vite 后完成验证。
