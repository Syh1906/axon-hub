## 推荐方案

在当前项目下增加独立的“密钥分组”页面，以分组代表实际使用者，以组内密钥代表该使用者的不同工具或设备。管理员可以继续只维护一个 Axon 项目和一个后台账号。

借鉴 CCH 的“用户行展开密钥”和“创建用户同时创建密钥”，增加适合日常分发的批量清单。保留 Axon 的主题、项目边界、密钥权限、配置模板及两层额度机制。

| CCH 中的对象或交互 | Axon 对应设计 |
| --- | --- |
| 用户及其多把密钥 | 密钥分组及其成员密钥 |
| 用户额度、到期时间 | 分组共享额度、分组有效期 |
| 用户行展开后管理密钥 | 分组行展开后直接添加、复制、设置、查看用量 |
| 创建用户并生成首把密钥 | 创建分组并可同时生成首把密钥 |
| 用户启停、备注 | 新增分组启停、备注 |
| 批量编辑时勾选要修改的字段 | 分别管理分组或密钥，只提交勾选的字段 |

CCH 界面中的“密钥分组／供应商分组”另有渠道选择含义，不能直接对应 Axon 的使用者分组。Axon 的分组不创建登录账号，不改变密钥的创建者或权限类型。

## 名称规则：同一项目、同一归属内唯一

“归属”指一个具体分组，或“未分组”这个独立范围。不同分组，以及未分组与某个分组之间，均允许同名。

| 当前情况 | 新操作 | 结果 |
| --- | --- | --- |
| A 组已有 `Codex` | B 组创建 `Codex` | 允许 |
| A 组已有 `Codex` | A 组再创建 `Codex` | 拒绝 |
| A 组已有 `Codex` | 未分组创建 `Codex` | 允许 |
| 未分组已有 `Codex` | 未分组再创建 `Codex` | 拒绝 |
| A、B 组各有 `Codex` | A 的 `Codex` 移到 B | 拒绝该项，提示改名或更换目标 |
| 未分组已有 `Codex` | 删除一个也含 `Codex` 的分组，成员移为未分组 | 先处理重名，不能直接删除分组 |

因此首把密钥可以默认叫“主密钥”，不必强制添加使用者前缀。分组自身的名称仍在项目内唯一，配置模板的名称规则不随之改变。停用和归档继续保留名称占用；软删除后可复用，沿用当前密钥生命周期。

必须同时覆盖以下入口：

- 创建、重命名、移组、移出分组，以及同一次操作中的改名加移组，都以最终目标分组和最终名称查重。
- 批量操作检查清单内部与数据库现存记录的冲突。两个被删除的分组若各有 `Codex`，同时移为未分组时也会互相冲突。
- 删除分组保持“成员转为未分组、不删除密钥”的既有含义；若冲突，展示待解决密钥，支持明确改名或改选目标，不自动加后缀、覆盖、合并或删除密钥。
- 写入时保留当前事务与并发协调，不能仅依靠前端预检。无分组按空归属处理，不能使用会放过多个空值重名的简单复合唯一约束代替验证。
- OpenAPI 不带分组的创建仍创建未分组密钥，只在未分组范围查重，不额外扩张服务账号的分组管理权限。
- 名称查找增加明确分组条件；沿用前端已有约定时可使用 `groupRef=0` 表示未分组、正数表示具体分组。只传名称且唯一时仍能定位；存在多个候选时明确报重名，要求补充分组或使用密钥 ID，绝不任取第一条。读取、额度查询、修改配置、应用模板需一致调整。
- 日志、报表、批量结果同时展示“分组＋密钥名”，内部选择和提交始终使用稳定 ID，不用显示名称识别记录。

## 页面与单条操作

新增项目侧栏入口与拟定路由 `/project/key-groups`，保留 API 密钥页面作为全量密钥视图。现有“密钥分组”按钮跳转到新页面，避免同时维护两套管理界面。所有查询和操作显式携带当前项目，切换项目后清空旧选择与草稿上下文。

主行显示分组名称、备注、密钥数量、有效期、五周期共享额度和操作；展开后显示成员密钥。共享额度使用“可用／上限”，各周期分别展示，金额沿用六位小数。点击额度或有效期进入已有预算编辑内容，不把五周期配置另做成重复表单。

组内直接添加密钥时锁定当前分组，不再要求重复选择项目或后台用户。创建分组时默认提供“同时创建第一把密钥”，可主动关闭。模板、个人额度、有效期与 IP 限制均可选；模板沿用当前应用机制。单条与批量创建保留现有权限类型及默认个人类型，服务账号继续显式配置 scopes。

“创建后继续添加”先显示刚生成密钥的结果，由用户复制或选择继续；继续时保留当前组与配置草稿、清空名称，不隐藏尚未处理的生成结果。转入批量清单时带入当前分组和已填草稿。

分组备注与启停需要新增后端字段。停用分组只阻止其成员继续发起请求，不把每把密钥自身的启用状态改掉；恢复组后，原先单独停用的密钥仍停用。状态摘要区分手动停用、到期和额度阻塞。分组管理仍由项目管理员操作，个人密钥可见性和管理权限保持现有边界。

“未分组”是特殊整理入口，不伪造成有独立 ID 的真实分组，没有共享额度、组启停或组删除操作。

## 批量创建：统一设置与逐行覆盖

### 批量创建分组

1. 粘贴使用者名称，一行一个；从 Excel 粘贴多列或导入 CSV 时先核对列对应关系，再加入清单。常用列是分组名称、备注；没有列头的一列按分组名称处理。
2. 设置共享额度、有效期等公共值，可为空。开启“为每组创建初始密钥”后，维护一份名称和配置清单，例如 `Codex`、`Claude`；每个分组生成同一套密钥。
3. 表格内可改名称与备注，也可为某一行覆盖额度、有效期或初始密钥清单。多个密钥以固定高度摘要显示，完整编辑按需打开，不把父行撑高。
4. 公共值变更只影响仍“沿用统一设置”的行；已单独调整的行不被覆盖，并提供“恢复沿用统一设置”。
5. 展示准确总数及冲突。预览例子 C、D 各两把，E 一把，共三个分组、五把密钥；第四行 A 与现有分组重名，不提交。

批量建组遇到已存在的分组，不自动变成向该组加钥；用户可改名、移除该行，或转到“批量添加密钥”处理。

### 批量添加密钥

提供两个输入方式，最终进入同一个可编辑清单：

- **每组添加同一套**：多选目标分组，输入多个密钥名称，生成组合。例如三个分组各加“手机”“备用”，明确显示六把。只有一个分组时也是同一流程。
- **逐行指定分组和密钥**：直接粘贴“分组、名称、模板”等列，每行独立指定；适合不同使用者需要不同数量、名称和配置。未分组是可明确选择的目标，不把空白或未知名称自动当成未分组。

例如以下是虚构清单，不要求每个分组有相同名称或数量：

| 所属分组 | 密钥名称 | 配置模板 |
| --- | --- | --- |
| 使用者 A | Codex | 研发默认 |
| 使用者 B | Codex | 研发默认 |
| 使用者 B | Claude | 研发默认 |
| 未分组 | 临时测试 | 不使用模板 |

生成清单后可逐行改组、名称、模板、单钥额度、有效期，也支持复制行、删除行、仅看冲突。类型、scopes、IP 限制等额外配置放在公共设置与单行详情中，不强行扩宽主表。

从生成方式转为逐行编辑时保留已填内容。再次生成组合或替换导入清单前明确“追加／替换”，已调整内容不能无提示消失。粘贴主要编辑数据表格，普通单字段保留正常文本编辑行为；支持 Tab、Shift+Tab、Enter，并保留整次粘贴的撤销能力。

### 冲突、提交与结果

- 预检标记名称重复、目标分组不可用、模板无效等具体行，并定位对应单元格。跨组同名不是冲突。
- 有冲突时允许明确提交选中的有效行，按钮显示实际分组／密钥数量；未提交行保留。不能静默跳过后报告全部成功，也不让一条错误无依据地阻塞其他行。
- 每个“新分组＋该组全部初始密钥＋选定设置”作为一个完整写入单元，成功才交付结果；单独批量加钥则以每把密钥及其选定设置为单元。避免组已建好但初始密钥或限制只保存一半。
- 不同单元可以分别成功或失败，结果逐项可核对。提交携带稳定批次／行标识；重复点击或响应中断先查询原结果，不重复生成已成功密钥。重试仅针对结果明确的失败项。
- 成功结果按分组整理，保留分组、密钥名称、状态与失败原因。提供每组复制、复制选中结果、主动导出 CSV，以及复制 API 地址／自助用量入口。密钥默认遮盖，复制或导出原文由用户主动触发，不自动下载或发给使用者。
- 设计阶段只设计上述流程；后续实施仅使用隔离本地验收数据库创建合成分组与密钥，没有导出含凭据的清单。

## 批量管理：明确对象、明确修改字段

点击“批量管理”后选择“分组”或“密钥”。分组模式只选择真实分组，组内密钥不作为独立选中项；密钥模式选择成员密钥，可按组选择其可操作成员，并明确成员数量。切换模式清空旧选择，页面显示正在修改哪类对象。正常模式保留明确的展开按钮和组名入口，选择框与展开动作分开。

默认“全选”仅作用于当前页；不把筛选匹配总数或尚未加载的数据静默纳入。翻页或跨页保留选择时按 ID 保存并持续展示数量，提供选中项清单；切换项目必须清空。

| 管理对象 | 主要操作 | 边界 |
| --- | --- | --- |
| 分组 | 给所选组添加密钥、修改共享额度／有效期／备注、启用／停用、删除分组 | 停用不覆盖成员自身状态；删除先解决成员转未分组的冲突 |
| 密钥 | 应用配置模板、修改独立额度／有效期／IP 限制、移组、启用／停用、归档 | 不修改共享额度；名称冲突按目标组检查，沿用每把密钥原有权限 |

编辑表单区分三种意图：不勾选为“保持不变”；勾选后可“设为具体值”；明确选“移除限额／永不过期／清空备注”才清除。空白不是清除指令，数值不合法应定位错误。

保存前显示选中对象、字段与变更摘要。预算只更新选定周期，其他周期、已用与暂占不被重置；续期不恢复额度。周期模式和生效时机遵循已有预算规则；若某组原来没有该周期，提交前明确新建周期的模式、时区和刷新时间。图中自然日 00:00、Asia/Shanghai 只是展示实例，不硬编码所有项目。

批量修改依照对象的当前版本回读和提交；出现并发变更的对象重新核对，不用旧整表覆盖未选择字段。手动额度重置继续使用独立、明确的现有重置流程。
