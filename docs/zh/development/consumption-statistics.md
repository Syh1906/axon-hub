# 用量统计与消耗排行榜

项目的「用量统计」提供密钥分组、模型、密钥、用户四个维度；管理区的「消耗排行榜」另有渠道维度，并提供消耗榜、缓存命中率榜。密钥指 AxonHub 签发给调用方的 API Key。界面不读取完整 Key。

这项 fork 功能的字段和算法移植自 `claude-code-hub` 的 `0c508eaa`。来源是该版本的 `src/repository/leaderboard.ts`、`src/repository/provider-cache-effectiveness.ts`、`src/lib/request-outcome.ts`、`src/lib/cache-effectiveness/{gate,service}.ts` 和 `src/app/v1/_lib/proxy/affinity/fingerprint.ts`。原项目 MIT 许可保存在 [LICENSE.cch](../../../internal/pkg/usageanalytics/LICENSE.cch)。CCH 没有独立密钥榜，本实现将其用户榜语义扩展到 Key。

## 范围与权限

| 入口 | 数据范围 | 权限 |
| --- | --- | --- |
| `/project/usage-stats` | 当前项目，前端显式传入 `X-Project-ID` | 当前项目的 `read_requests` 或系统所有者 |
| `/leaderboard` | 默认全站，可筛选单个项目 | 系统级 `read_leaderboard` 或系统所有者 |

排行榜只有查看权限，不定义管理权限。菜单、路由和后端查询都执行权限检查；项目级同名权限不授予全站访问。项目筛选选项由专用 `consumptionProjects` 查询提供，只有排行榜权限也能使用，不要求额外的项目管理权限。排行榜查询忽略顶部当前项目，不会意外缩小全站范围。权限检查先于查询缓存读取。

项目用量按「密钥分组 → 模型 → 密钥 → 用户」排列，默认选择密钥分组，点击分组名称展开模型明细。具备项目读取权限时包含其他成员的个人 Key 请求；写入权限和跨项目隔离保持独立。

消耗排行榜按「渠道 → 密钥分组 → 模型 → 密钥 → 用户」排列，默认选择渠道。

独立模型维度按最终调用模型名称合并各渠道的请求，无执行模型记录时使用请求模型。统计包含当前记录与归档记录，同名模型合并为一行，支持模型名称搜索。模型行直接展示请求数、成本、Token 数、成功率、平均首字耗时、平均输出速度和整体缓存命中率。模型缓存榜展示缓存触发请求数、命中率、缓存读取／输入 Token、平均首字耗时、平均输出速度及对应请求成本。有效样本缺失时显示「—」。模型名称左对齐，数值居中。

## 日期、排序与展开

两页共用今天、昨天、本周、本月、全部、指定日期。日期由后端按系统时区计算，本周从周一开始。指定日期传 `YYYY-MM-DD` 起止日，结束日包含整天；内部使用开始日零点到结束日次日零点的左闭右开区间，适用夏令时的 23／25 小时自然日。结束日早于开始日时拒绝查询。

数据库时间由 Ent 统一保存为 UTC。自然日边界先按系统时区计算，再转换为 UTC 参与查询；缓存汇总的时钟和窗口也统一为 UTC。这样 SQLite 的文本时间比较不会把午夜请求归到错误日期，或因服务器时区不同漏掉缓存样本。

「全部」表示保留在系统中的全部请求；清理请求或用量会改变可查询的历史。用户、密钥、渠道切换保留时间范围。表头可排序，排序不改变已展开对象；展开明细随对应父行移动。宽表格在表格区域滚动，模型子行使用连续浅灰底；悬停或键盘焦点进入一行时，整行单元格使用统一主题底色，行高不变、不缩放。候选列表、下拉菜单与轻量按钮使用同一悬停色，深色主题和减少动画偏好独立适配。

表格只挂载可视区域及前后少量行，展开的模型也参与可视区域计算，避免密钥数量增加时一次创建全部单元格。行使用实际高度和普通表格流排列，列宽不随滚动改变。前端读取周期与内存缓存见下方「页面读取与浏览器缓存」；后端保留一分钟结果缓存，密钥显示名只读取 ID、名称、用户、项目和分组字段。

名称搜索支持用户显示的完整姓名、姓名片段和邮箱，忽略大小写。密钥、渠道和模型按各自名称搜索。数值按列居中，排序／展开图标及模型数量不改变文字的对齐位置。

## 请求与金额归属

金额显示精度可在「系统设置 → 常规 → 金额显示小数位数」调整。默认「保持现有精度」沿用各页面原来的位数；管理员选择 0–8 位并保存后，消耗排行榜、项目用量统计、密钥分组和 API 密钥的成本／额度展示按该位数四舍五入并补齐尾零。普通项目用户也会读取该展示设置。切回默认可恢复原来的显示规则。

此设置仅影响前端显示，不修改存储金额、接口返回的成本／额度、统计计算、排序、额度输入值或预算判断。例如原金额 `1.23456789` 选择 2 位后显示为 `1.23`，参与计算的仍是原金额。

按已经结束的请求统计，每个请求只计一次，并归属到其最终渠道。执行记录提供实际模型、响应状态和耗时，不将失败重试额外算作请求。用量先按请求、渠道、项目汇总，再关联最终渠道的最后一次执行，避免执行数与用量行相乘。模型按实际执行模型分组，没有实际模型时使用请求模型。

成本直接累加保存的历史 `total_cost`，不按当前价格重算，不影响定价和路由。界面显示已有依据的金额，不附加「部分未计价」、星号或计价覆盖次数；全部缺少费用依据时显示「—」，明确记录为零的费用仍显示零。单次成本只使用费用完整的请求；每百万 Token 成本进一步要求该请求有输入／输出 Token，费用与 Token 来自同一批样本。单条缺少依据不隐藏其他有效样本的均价；没有有效样本才显示「—」。明确记录为零的费用参与计算，无 Token 的按次费用不混入 Token 均价。总 Token 使用 AxonHub 的输入加输出；输入已经包含缓存部分，不能再加一次缓存读取／写入量。

按 CCH 的实体过滤规则，删除的用户、渠道不出现在各自榜单；Key 榜同样排除已删除 Key。用户榜仍可归集该用户已删除 Key 的保留请求记录。删除对象和清理日志与新统计页面无关，排行榜不提供删除或修订历史金额操作。

`total_cost` 是本次请求最终价格、计费档位和实际渠道／Key 倍率共同确定的实际成本，不使用标准成本替代，也不在计算均价时再次乘倍率。例如标准计费小计为 3、最终倍率为 0.25、有效样本为 110 万 Token 时，实际费用为 0.75，每百万 Token 成本约为 0.681818。迟到的有效结算证据与未计价用量记录一起补全，避免预算已扣款而排行榜仍未计价。

## 模型明细

| 榜单 | 模型子行字段 |
| --- | --- |
| 用户／密钥／密钥分组消耗榜 | 模型、请求数、总 Token、整体缓存命中率、成本 |
| 渠道消耗榜 | 模型、请求数、成本、总 Token、成功率、平均首字耗时、平均输出速度、单次成本、每百万 Token 成本、缓存系数、整体缓存命中率 |
| 用户／密钥／密钥分组缓存榜 | 模型、缓存触发请求数、命中率、缓存读取 Token、总输入 Token；成本列显示「—」 |
| 渠道缓存榜 | 模型、缓存触发请求数、命中率、缓存系数、缓存读取 Token、总输入 Token |

- 整体缓存命中率（消耗榜及用量汇总）：全部缓存读取 Token ÷ 全部输入 Token，包括未命中缓存的请求；分母为零显示「—」。
- 缓存触发请求（缓存榜）：至少有缓存读取或写入 Token 的请求。命中率＝这些请求的缓存读取 Token 总量÷输入 Token 总量，限制在 0–100%。不把每行百分比相加或平均，不把未触发缓存的请求放进分母。
- 单次成本＝完整计价请求的费用÷完整计价请求数；每百万 Token 成本＝完整计价且有 Token 的请求费用×1,000,000÷这些请求的输入与输出 Token。分母为零时返回空值并显示「—」。归档统计沿用相同样本规则；旧归档费用完整性未知时不冒充完整样本。
- 渠道页「今日各模型用量」提供平均首字（ms）、平均输出（tok/s）、成功率及每百万 Token 成本，不附加计价覆盖提示。三项性能指标沿用下述有效样本规则，仅统计已结束请求；没有有效样本时显示「—」。列表金额、浮层成本汇总及各模型成本统一遵循系统设置的显示小数位，未设置时保留原有 6 位显示。
- 明细只在打开浮层时查询，不随整个渠道列表预加载；打开时每 30 秒刷新，关闭停止轮询。浏览器将明细保留 5 分钟、20 秒内复用；服务端最多保存 64 个渠道／自然日的结果，10 秒内复用并合并并发查询。权限每次重新检查，事务内读取不使用共享缓存；跨自然日使用不同缓存键。关闭或快速重开只取消该次等待，不中断其他调用方共享的计算；共享计算最长 30 秒。后端以同一数据库读取快照按渠道、日期及稳定游标分批查询，每批同时读取最终执行和用量，避免重复扫描与重复加载历史价格；历史费用及标准成本口径保持不变。
- 成功率采用 CCH 的成功／失败／排除分类，在 AxonHub 的执行状态上对应实现。404、额度／限流错误和已收到首字节后的客户端取消排除；新请求在首字节之前取消计失败。旧取消记录无法确定是否收到首字节时保持排除。本地队列满、排队超时、RPM 耗尽可能已创建执行记录，但尚未向供应商发出请求；凭本地拒绝的 429 状态与对应错误消息排除这些样本，保留请求数和历史金额。普通上游 429 不因状态码相同而自动排除。没有有效结果时显示「—」。
- 平均首字耗时使用已有的首个有效输出时间。首字节另行采集，记录读取上游响应正文的第一个字节，既不是响应头时间，也不等待完整 SSE 事件。Responses WebSocket 在消息读取器上观察首个载荷字节，不等待全部分片；Vertex 转换请求时保留同一观察回调。
- 输出速度逐请求计算 `输出 Token × 1000 ÷ (总耗时毫秒 - 首字节耗时毫秒)`，再对有效值求平均。仅纳入可唯一对应最终执行的流式文本请求，排除非流式、图片／音视频输出、缺失时间、无输出、首字节不早于结束以及差值不足 100ms 的样本。Gemini／Responses 等文本协议还检查保存的图片证据；语音输出检查用量记录。消费榜展示有效样本数；请求日志、模型分析、性能曲线和渠道探测均复用该公式。两条有效请求分别为 100 和 500 tok/s 时，平均为 300，而非用总 Token 除以总耗时。内部路由评分算法不由此改变。
- 有已确认部分输出的失败、取消请求也可成为测速样本；模型分析的父行和渠道明细显示有效样本数。模型分析与渠道探测的请求尝试数、成功率分母仍只计成功／失败，首字时间仍只取成功执行。最终执行统一按执行 ID 选择，时间戳相同的重试不会漏掉最终样本。

消耗榜默认按成本降序。用户／密钥／密钥分组缓存榜按命中率、请求数降序；渠道缓存榜先按缓存系数，再按命中率、请求数降序。缺失值置后，平局以实体 ID 或模型名保持稳定顺序。

## 缓存系数

只采集支持的对话格式：Anthropic Messages、OpenAI Chat Completions／Responses、Gemini Contents。按 CCH 规范化工具、系统提示与消息，生成摘要和前缀字节数；理论可缓存量为规范化字节数除以 4 向下取整。摘要区分项目、调用方 Key、格式和请求模型，不保存提示词正文。它只标记统计样本，不参与会话复用或路由。

成功完成且有上游用量的最终执行才是有效样本；失败、取消、截断和缺失用量仍计入可观测样本总数，但不累加理论量或实际读取量。按项目、最终渠道、模型、5m／1h TTL 桶汇总。现有调度器每 5 分钟执行一次，预留 15 分钟终态缓冲；首次运行回看 1 小时，后续从最后窗口续接。固定 5 分钟窗口与唯一键、upsert 避免多实例重复累计，空闲时段直接跳到下一条样本。

跨模型、TTL 或时间窗口汇总时，先累加计数和 Token，再重算系数，不能平均已有分数。计算使用整数万分比：

```text
实际比例 = clamp(实际缓存读取量 × 10000 ÷ 理论量, 0, 10000)
样本量修正 = 有效样本 >=100:10000；>=30:6000；>=5:3000；其余:1000
可观测比例 = 有效样本 × 10000 ÷ 全部样本
置信修正 = 可观测比例 × 样本量修正 ÷ 10000
缓存系数 = 实际比例 × 置信修正 ÷ 10000
```

每步除法截断；界面再除以 10000 展示为 0–1。没有窗口样本时显示「—」。通常滞后约 15–20 分钟，超过缓冲时间才结束的请求可能不进入该窗口的有效样本，和 CCH 的展示级统计边界一致。成本及缓存命中率独立更新。

## 查询、存储与升级

后端入口为 `ConsumptionService`，GraphQL 定义见 [consumption.graphql](../../../internal/server/gql/consumption.graphql)。父行和模型明细一次分组查询，浏览器不下载原始日志计算。搜索在后端执行，前端延迟 300ms 提交；结果缓存 1 分钟，键包含视图、项目、日期、时区、币种、维度、指标和搜索条件。

Ent 新增 `cache_effectiveness_windows`，并给 `request_executions` 增加可空的首字节时间、采集标记、缓存摘要、理论量和 TTL 桶。字段及索引由 Ent 生成管理，不手写 schema SQL，不增加 data migration 版本；已对照直接上游 `v1.0.0-beta10-fork.7`／`b205ae8e`，没有同名字段或迁移冲突。原始上游仍独立记录在 `release.config.json`。

`usage_archives` 新增可空 `pricing_complete` 与默认 0 的 `speed_version`。新归档记录费用完整性及修正后的速度版本 1；旧归档无法恢复逐请求依据时不参与新速度平均，费用完整性标记未知，不把旧零值视为已确认免费。两个字段由 Ent 自动迁移，不改已发布的数据迁移。

旧请求的缺失采样保持 NULL，不回填猜测值，已有耗时与成本不变。SQLite 已验证旧 schema 升级、重复升级、历史字段保留和窗口唯一约束。SQL 使用各方言共有的聚合表达式，upsert 由 Ent 按方言生成；MySQL／PostgreSQL 实例升级尚未验证。

## 密钥分组

密钥与分组维度均可筛选指定分组，候选项来自当前统计范围内有用量的分组。无分组与已删除密钥不参与分组榜，同名但不同项目的分组按独立编号统计；全站范围在组名后附项目名称，选择单个项目时保留原组名。历史用量按当前成员关系聚合；分组改名或移组会更新缓存版本，不等待原结果过期。权限沿用各页面原有边界。分组创建、默认筛选和自助查看说明见[API Key 自助用量](../guides/self-usage.md#管理密钥分组)。

## 页面读取与浏览器缓存

管理端普通数据读取最多等待 35 秒，包含响应正文读取；初始化与当前用户检查最多等待 10 秒，失败后可手动重试。写操作、渠道测试与模型流式请求保留独立契约。切换或离开已接入取消信号的页面时停止旧读取，超时不连续自动重试。

排行榜和项目用量的昨天／指定日期每 5 分钟重新读取，其余范围仍每分钟刷新，手动刷新不受影响。浏览器内存保留闲置统计与模型列表最多 5 分钟；保留缓存不等于永久固定历史费用，重新进入时仍按新鲜度检查更新，不将业务数据写入长期离线存储。金额显示复用有界格式器，统计值与小数位语义不变。

PostgreSQL 无搜索、无指定密钥分组的排行聚合一次选取各请求在同项目、同渠道下的最终执行及统计字段。带搜索或指定分组的查询仍使用按请求索引查找，避免小范围筛选扫描整个时间范围的执行。其他方言、归档及小批量明细保持原路径；统计口径和权限不变。

模型表格只渲染可见行及少量缓冲行；排序、开发者分组和全选仍基于完整已加载列表，滚出视区不清空显式选择或展开状态。接口目前仍先取完整模型列表，没有将大列表渲染优化描述为接口分页优化。
