# Request log and execution diagnostics maintenance record

## Loading and refreshing the request list (rc1-fork.29, 2026-11-28)

PostgreSQL looks for the previous adopted execution in the same project and session, starting with the preceding 128 request IDs. If this range has no eligible execution, it searches older history. An unchanged channel means reuse. Only a channel switch requires checking whether the new channel was used earlier in the session.

When a paginated request query includes computed fields such as usage, speed or continuation count, it retains the metadata needed by resolvers. It reads headers, bodies, response chunks and routing decisions when the GraphQL selection requests them. When merging upstream, check the [Ent pagination template](../../../internal/ent/template/pagination.tmpl), the [field selection](../../../internal/ent/gql_request_list_fields.go) and the regression for explicitly requested headers.

A read-only comparison used a fixed sample of the latest 50 requests at each deployment. Both original channel-history queries exceeded the four-second measurement limit. Across three runs of the replacement query, execution took 128–212 ms at the Quange deployment and 134–169 ms at Yunyou. These timings cover database execution. End-to-end measurements on those deployments are pending release.

Numbered pagination fetches the total for the same project and filters separately. The current list response controls navigation to adjacent pages. Once the total arrives, the user can jump to a page or the last page. Manual refresh updates the total. Automatic refresh updates it at most once a minute. Scrolling mode needs no total.

The initial filter and diagnostics implementation shipped in `.syh.7` at `30c46355`. Its maintenance contracts are as follows.

- The request page defaults to today in the reporting timezone. It supports yesterday, week, month, all time and custom times down to the second. Channel tags, channels, key groups (including ungrouped keys) and keys can be combined. Values within a filter use OR. Separate filters use AND. The URL retains the filters and changing them returns to page one.
- The status area shows the client HTTP status and retry count. Channel cells show session state, tags and the selected key's remark or suffix. The provider has its own column. The model ID can be copied. Cache reads and writes are separate and writes do not increase the hit-rate numerator. Streaming speed excludes first-token latency. Missing measurements stay unknown.
- The session badge shipped in `.syh.17`. Each finished request contributes its last dispatched channel. Upstream failure still counts. Attempts blocked locally before dispatch do not count. Requests without a dispatch remain available in diagnostics. Historical rows use their existing matching rules without a backfill. The list, route detail and channel filter share the same channel attribution.
- Each attempt preserves its routing and key snapshot, error source, redacted provider error and actual retry or stop decision. Stored provider error responses follow the body retention policy with a 64 KiB limit. Older records can display an unknown value. The client status and provider status are separate. Reading routing snapshots requires `read_channels`.
- The reporting timezone is available with `read_requests`. Project queries carry project identity. Attempts clear the previous key on retry. The stream records the reason for a client disconnect after delivery starts. A pre-read failure retains the original retry behavior.
- The optional channel website is independent of the API address. It accepts HTTP(S) URLs without embedded credentials. Save, copy and backup restore preserve it. Channel names retain global uniqueness.
- Group usage is available to administrators for the current project's member keys, including disabled keys and empty groups. Group, single-key and self-service views default to the last seven days following the 2026-11-05 adjustment. Management caches separate users, projects and groups. Self-service remains scoped to the calling key.
- Upgrade fields include nullable `channels.website_url`, `requests.client_status_code` and execution selection, failure and retry decision. Ent manages the schema. Historical snapshots have no backfill. SQLite upgrades, repeated upgrades and retention of existing values were tested at the time.
- When merging upstream, check overlapping Ent and GraphQL fields, execution middleware ordering, the stop-retry observer, scope checks for group usage, and the frontend request and group usage components. Original fixtures covered combined filters, daylight-saving boundaries, stopped keys, routing snapshots, redaction, channel websites and stream speeds.
